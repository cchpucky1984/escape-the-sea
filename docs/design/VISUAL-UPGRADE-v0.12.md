# 逃出大海 · v0.12 視覺升級定案（WebGL2 渲染層）

> 作者 A（PM／主企劃）· 2026-11-05 · 決策：**留在 Web、升級渲染層到 WebGL2**（使用者拍板 A）。
> 基準 `v0.10.0-alpha`：純 Canvas 2D 單一 `<canvas>`＋DPR 縮放（`main.js:115`）、FX 已有 tier1–3 自動降級（`fx.js:117-141`）、海面已有大量 `globalCompositeOperation='lighter'`（`sea.js:379-1185`）。海面極限場景 headless **29–33fps**（`_shots/D10/perf.json`）。
> 只寫 `docs/design/`；不跑 git、不改 `js/`。
## 0. 架構決策：加「合成層」，不重寫繪製
- **混合架構**：現有 Canvas2D 場景照舊畫到 offscreen → 上傳成 WebGL2 texture → post chain（bloom／additive 加色／caustics 焦散／暗角／色差）→ 輸出到螢幕。新檔 **`js/gl2.js`（D 擁有）**，`fx.js` 只負責粒子資料。
- **為什麼不全改 WebGL**：現有繪製碼 sea 1.4k／base 1.0k／space 2.5k 行（全程序繪製、無貼圖），改寫 ≥15 人日且會弄壞已驗收的場景；使用者的需求是「看起來值 $2.99」，不是換引擎。合成層 3–4 人日就能拿到 80% 的視覺提升。
- **本輪範圍（Lead 裁決）**：**只做合成層**。完整 Renderer 遷移排 **v1.1**；B 的 `docs/tech/WEBGL-INTEGRATION.md` 保留為長期設計，**不在 v1.0 範圍**——不遷移既有繪製，B 只留 Renderer 抽象骨架不接線。
- **保底**：偵測不到 WebGL2 或 fps 不達標 → 自動回 Canvas2D（現況），功能完全不減；`?gl=0` 可手動強制。
- **HUD 不吃 post**：DOM HUD 疊在最上層，bloom 只作用於世界層（避免文字發光、糊掉）。
- **瀏覽器支援**：WebGL2 需 Chrome 56+／Firefox 51+／Safari 15+；iOS 15 以下與舊 Android → fallback（估計 <5% 流量，可接受）。
- **P0 分工（核准版）**：**D 5.5 人日**＝`js/gl2.js` 合成層＋bloom＋caustics（3.0）＋爆炸三段（1.0）＋命中回饋（1.5）；**B 1.5 人日**＝接線（`main.js` 開關、`?gl=0/1`、`__T`／QA hook、fx 整合）——含在 7.0 buffer 內、不另計。C＝「畫質」設定 UI；Lead＝QA 的 GL on/off 兩組。
- **QA 影響**：`tools/qa.mjs` 要各跑一次 `?gl=1` 與 `?gl=0`（boot＋六場景＋fps 取樣），兩邊 `pageErrors=0` 才算過。

## 3. 裝置分級與降級
| 級 | 判定 | 解析度／DPR | 效果 | fps 門檻 |
|---|---|---|---|---|
| desktop-high | 前 5s fps ≥50 且有 GPU | 1280×800、DPR 1（retina 上限 1.5） | bloom 4 段、caustics 2 層、CA/vignette on、粒子 900 | ≥30（目標 60） |
| desktop-low | fps 35–50 或 iGPU | 同上 | bloom 2 段、caustics 1 層、CA off、粒子 500 | ≥45 |
| mobile | UA＋touch | DPR cap 1.5、post 半解析度 | bloom 2 段、caustics 1 層低頻、粒子 400、無體積霧 | ≥24 |
| fallback | 無 WebGL2／`?gl=0` | 現況 Canvas2D | 現有 fx tier 1–3（`fx.js:117`） | ≥30 |
- 切換：設定面板加「畫質：自動／高／中／低」（`settings.quality`，預設自動）；自動＝每場景量 5s，低於門檻降一級、**只降不升**（沿用 `fx.js` 現有邏輯）。
- **reduce motion**：CA／vignette／震動／hitstop 全關，bloom ×0.5，粒子降到 500——與現有 `installFxAccessibility()`（`core.js:189-201`）一致。

### 「不要做」清單（做了會拖垮上架）
- 全部改成 WebGL 管線（重寫 5k 行繪製）；SSAO／即時陰影／真反射／體積雲；PBR／法線貼圖／外部素材（本作無圖檔資產）；手機 4K post；粒子 >2000；用 CSS filter 做 bloom；改掉現在的程式繪製美術風格；為了畫面犧牲可讀性（HUD 對比、子彈可見度）。
## 5. 與 v1.0 其他 blocking 的時程關係
- **新增 blocking V1：GL2 合成層（P0）**——但**不延後 beta**：封測照 `BETA-KIT-v0.10` 跑，用 `?gl=0` 保底；GL 只影響「商業級視覺」這一項評分，不擋 8 人測試。
- **不延後上架窗**：P0 7 人日可與 beta 招募／平衡 log 並行（D 5.5 為主、B 接線 1.5）。**go/no-go＝D5（Lead 定義：S2 合成層落地、`tools/qa.mjs` 47+ 全綠那一輪，約 2 個工作天後）**，判定：① P0 未成（build 仍未帶 GL 合成層）或 ② mobile 量不到 ≥24fps → **v1.0 用 Canvas2D 版上架**（現況已可），GL 排 v1.1；反之就上 GL。
- **與其他 blocking 的序列**：B1 首輪長度（平衡）先定案 → GL P0 並行 → B3 實機測試**必須含 GL on/off 兩組** → B2 效能改用 GL 後重測（預期淨持平：省掉大量 canvas radial gradient，多 1.5–2ms post）。
- 若 GL 成功，v1.0 的「商業級視覺」由 🟡 部分 → 🟢 已達；這是六大支柱裡**唯一能靠一輪工程直接翻綠**的一項。
