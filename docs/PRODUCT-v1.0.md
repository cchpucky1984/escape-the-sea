# Escape the Sea — 商業級品質標準（v1.0 目標）

> Lead 制定 · 2026-11-04 · 這是「打磨到商業級」的定義與驗收尺，所有工單都要對得上其中一條。
> 假設（使用者未反對前以此為準）：**web-first**（itch.io＋GitHub Pages，之後再評估 Steam 打包）、**zh-Hant＋en** 雙語、**一次性買斷**（$2.99–4.99）、**無帳號／無雲端／無廣告／無內購**、單人離線。

## 0. 一句話定位

> 一款 90–150 分鐘一輪、可重玩、有明確結局的深海生存 × 基地建造 × 星際復仇小品；像 Dave the Diver 的節奏、Dome Keeper 的基地壓力、Vampire Survivors 的短迴圈。

## 1. 六大支柱與門檻（可量測）

| 支柱 | 商業級門檻（v1.0） | 現況（v0.4.0-alpha） |
|---|---|---|
| **A. 內容深度** | 首輪 90–150 分鐘；20+ 任務；3+ Boss（含最終）；4 種海域事件；重玩有變化（隨機事件／成就／挑戰模式） | 首輪約 55–70 分鐘（試玩 5 分鐘就撞決戰）、11 任務、4 守衛＋核心、0 事件 |
| **B. 上手與 UX** | 前 3 分鐘有明確下一步；任何時間 HUD 都有「現在該做什麼」；無死路（每個擋門都有提示與導航）；首次死亡 ≥5 分鐘；載入 <2s | 8 分 45 秒完全沒目標（A 的試玩報告）、開局 toast 與「要游回基地」矛盾、無導航 |
| **C. 視聽品質** | 3 段以上背景音樂（海面／升空／母船）＋環境音；20+ 音效；命中/擊殺/受擊回饋一致；HUD 與概念圖同一套色票；1280×800 穩定 60fps、390×844 ≥30fps | 完全沒有音樂；9 個合成音效；FX 剛建立；headless 33–35fps（軟體渲染，實機待量） |
| **D. 技術品質** | 自動化 QA 全綠且 commit 前必跑；0 console error；存檔 100% 可靠（含 v1→v3 遷移）；所有場景可達；崩潰率 0 | `_dev/qa.mjs` 33/33 綠；存檔 v3 有 fixture；軟體渲染下 pageErrors 0 |
| **E. 可及性與本地化** | zh-Hant＋en 全字串；音量/靜音滑桿；減少動態（reduce motion）；不靠顏色辨識（形狀/文字輔助）；鍵盤全可用；字級可放大 120% | 只有 zh-Hant；只有 M 靜音；無 reduce motion；部分色碼區分 |
| **F. 發售準備** | itch 商店頁上線；Steam 願望清單頁（可選）；5 張商店截圖；30 秒預告；press kit；隱私聲明；版權/素材清單；價格與分級 | 商店文案草稿、8 張概念圖＋8 張商店候選；無預告、無 press kit、無上架 |

## 3. 每輪的完成定義（DoD）

1. 工單對應到 §1 的支柱與門檻
2. `_dev/qa.mjs` 全綠（新增功能要加檢查）
3. 有玩家視角驗證（可自動腳本＋至少一次真人式試玩）
4. 文件更新（GDD／AUDIT／ROADMAP 對應段落）
5. Lead 本地 commit；未經使用者同意不 push

## 5. 風險與取捨

- **不要為了「像商業遊戲」而堆系統**：每個新系統都要回答「它讓哪一段時間變好玩」，否則退回。
- 音樂如果 ace_step 產出不可用，就退回 WebAudio 程序化配樂（B 有合成器基礎），不要卡住里程碑。
- Steam 打包（Electron/Tauri）不在 v0.5 範圍；先把 web 版做到值得收費。
- 每次改動都可能破壞存檔：`_dev/fixtures/` 的 v1/v2 樣本必須持續通過。
